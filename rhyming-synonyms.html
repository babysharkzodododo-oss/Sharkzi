How a hit is confirmed

A word is a hit when it appears in both the meaning set and the rhyme set for the query — sets built from separate requests and intersected here, in the page. That intersection is the source of truth. The single combined request (rel_syn=…&rel_rhy=…) is issued as well and reported per row under Server combo, but it does not gate anything: where the two disagree the client-side intersection wins, because it is set algebra over words the API itself returned for each constraint alone.

Rich rhymes. Datamuse counts bemoan as a rhyme for moan and as related in meaning, so affixed forms of the same root sail through both constraints and are the most common false positive here. Any pair where one word contains the other as a prefix or suffix is flagged root and dropped by default. The test is spelling, not etymology, so it is a heuristic — it will not catch every shared root.

Truncation. Intersecting two capped lists can silently lose hits, so each set is requested at max=1000 and any set that comes back at the cap is marked in the requests panel. A capped set means the result below is a subset, not the whole answer.

Ordering. Perfect rhymes before near rhymes, strict rel_syn evidence before ml-only, then by the meaning query's own score. Frequency, syllable counts and parts of speech come from md=dpsf on the same requests — no extra round trips — except the source word's own part of speech, which needs one sp= lookup and is fetched only when that filter is on.

Limits. Datamuse asks for no key but is not free to hammer: keep sustained traffic modest and scans small. Concurrency is capped at 10 here for that reason.
